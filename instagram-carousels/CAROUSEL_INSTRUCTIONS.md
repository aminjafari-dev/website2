## 2. Roles for future work

Use these roles every time a carousel is produced. One person/AI can wear multiple hats, but the checklist for each role must still pass.

### Role A — Strategist
- Pick the next topic from `TOPICS.md` (respect order unless overridden).
- Define the **one job** of the carousel (educate, convert, prove expertise, or announce).
- Write a one-sentence thesis the whole swipe must support.
- Choose slide count (default **10–12**; minimum **7**, maximum **12**).
- List proof points, stats, and CTA.

### Role B — Copywriter
- Write all slide headlines + body + caption + hashtags.
- Keep headlines **large and scannable** (max ~6–8 words when possible).
- One idea per slide. No walls of text.
- Primary CTA on slide 1 (soft) and final 1–2 slides (hard).
- Caption: hook in first line → short story → CTA → hashtags.

### Role C — Art Director / Designer
- Apply the visual system in §4–§5.
- Alternate dark / light slides for swipe rhythm.
- Place logo top-left on every slide.
- Use one dominant visual per slide (statue/icon/product/chart) — never clutter.
- Export Instagram-ready assets (see §8).

### Role D — Brand / Reviewer
Before publish, confirm:
- [ ] Sounds like Byto.tech (secure + AI + engineering)
- [ ] Logo, colors, and type match this doc
- [ ] No competitor logos misused; no fake client claims
- [ ] CTA is clear and consistent
- [ ] Slide order tells a story without reading the caption
- [ ] Topic matches `TOPICS.md` and can be marked done after post

### Role E — Publisher
- Upload as **carousel** (not single image).
- First comment: optional link or “DM ‘SECURE’ to start.”
- Tag relevant services only; avoid spam hashtag blocks.
- After posting: note date + URL in `TOPICS.md` under that topic.

## 3. What we take from the reference carousel

Study `reference-carousel-style.jpg`. Replicate these **patterns**, not the SMM agency look:

1. **Cover slide** — bold claim + strong hero visual + soft CTA.
2. **Menu / map slide** — list of what the carousel (or the agency) covers.
3. **Deep-dive slides** — each service or idea gets its own full slide with a big visual.
4. **Process / checklist slide** — numbered steps the viewer can follow.
5. **Proof / craft slide** — tools, platforms, or method (analytics, stack, security checks).
6. **Handshake / invite slide** — human/connection metaphor + discuss CTA.
7. **Final CTA slide** — direct question + strong button (“Start Your Project”).

**Rhythm rule:** Dark → light → dark → light… so each swipe feels like a new beat.

**Hierarchy rule:** Huge headline → one short support line → optional small list → visual does the rest.

**Logo rule:** Same brand mark, same corner, every frame.

## 4. Byto.tech visual system (carousel edition)

### 4.1 Color palette (use these — not purple/lime)

| Token | Hex | Use |
|-------|-----|-----|
| Navy deep | `#0F1E3F` | Dark slide backgrounds |
| Navy mid | `#213A56` | Secondary dark surfaces, charts |
| Cream | `#F5F0E8` | Light slide backgrounds |
| White | `#FFFFFF` | Text on dark, clean panels |
| Gold accent | `#CDAA80` | Highlights, icons, underlines, secondary CTA |
| Bronze | `#997953` | Supporting accent, graphs |
| Black | `#0A0A0A` | Optional ultra-dark slides, text on cream |
| Alert / emphasis | `#E8D5BC` or pure white | Soft highlights — not neon green |

**Accent for CTAs:** Gold/bronze solid buttons with navy or white text — high contrast, always readable.

Avoid: default purple gradients, neon lime, generic “AI purple glow” looks.

### 4.2 Typography
- **Headlines:** Bold geometric sans-serif (e.g. Space Grotesk, Satoshi, or similar). Large. Mix white + gold on dark slides; navy + bronze on light slides.
- **Body:** Clean sans, smaller, high legibility. Max 2 short lines under a headline unless it is a checklist slide.
- **No** decorative script for main claims. Small doodles (lock, check, crown) are OK as accents only.

### 4.3 Imagery language (classical × modern, Byto-flavored)

Borrow the reference idea of **high craft + modern tech**, adapted to security/engineering:

| Allowed | Examples |
|---------|----------|
| Classical / sculpture | Greyscale statue with modern prop (phone, laptop, padlock, VR glasses) |
| 3D gloss icons | Lock, shield, rocket, laptop with charts, mobile mockup, API nodes |
| Product UI | Real Byto project screenshots / phone mockups (prefer real work) |
| Texture | Torn-paper edges, soft navy/cream blobs, diagonal splits |
| Hands / connection | Stylized “reaching hands” for partnership / kickoff slides |

| Avoid | Why |
|-------|-----|
| Random stock smiling office people | Breaks the crafty, premium feel |
| Unrelated social logos as the hero | We are not an SMM agency |
| Fake metrics or invented client logos | Trust risk |
| Crowded icon rows | Kills hierarchy |

### 4.4 Layout rules
- Canvas: **1080 × 1350 px** (4:5) for feed carousels. Optional Stories size later: 1080 × 1920.
- Safe margin: **80 px** from all edges; keep logo and CTA inside the safe area.
- Logo: **top-left**, consistent size on every slide.
- One primary visual per slide; secondary elements stay supporting.
- CTA buttons: rounded rectangle, gold fill, navy text (or reverse on light slides). Place lower third.
- Torn-paper / diagonal splits: use on 2–4 slides max so the device stays special.

## 5. Standard 12-slide blueprint

Use this template. Shorten to 8–10 by merging “deep dive” slides if the topic is narrow.

| # | Bg | Role of slide | Content pattern |
|---|----|---------------|-----------------|
| 01 | Dark or accent navy | **Cover** | Big promise + hero visual + soft CTA (“Swipe →” / “See how”) |
| 02 | Light | **Map** | 3–5 pills or numbered items this carousel covers |
| 03 | Dark | **Problem / hook** | Pain the audience feels (e.g. AI ships insecure) |
| 04 | Light | **Pillar A** | First big idea or service |
| 05 | Dark | **Pillar B** | Second idea + checklist or tablet visual |
| 06 | Light | **Pillar C / brand line** | Memorable line + torn paper or crown/lock doodle |
| 07 | Dark | **Proof / method** | Analytics, security review, process visual |
| 08 | Light | **Craft / approach** | How we work differently |
| 09 | Dark | **Stack / domains** | Mobile · Web · AI (or topic-specific tools) |
| 10 | Light | **Journey** | Idea → Build → Harden → Launch (graph over terrain OK) |
| 11 | Dark | **Invite** | Connection visual + “Discuss your project” |
| 12 | Light | **Hard CTA** | Question + “Start Your Project” button |

**Always include:** slides 01, 02, 11, 12. Never end without a CTA.

## 6. Copy rules

1. **English** by default (match the website). If a campaign needs another language, say so explicitly in the brief.
2. Headlines punchy: “AI Builds Faster.” / “It Doesn’t Ship Safe.” / “We Build Beyond AI.”
3. Prefer concrete verbs: build, harden, review, ship, automate.
4. Stats only if sourced or already used on byto.tech (e.g. AI-code security risk framing from the site).
5. No emojis in slide headlines. Optional single emoji in caption only.
6. Caption structure:
   - Line 1: hook (same energy as slide 1)
   - 2–4 short paragraphs expanding the thesis
   - CTA + link-in-bio / DM prompt
   - 3–8 relevant hashtags (e.g. `#AIengineering` `#AppSecurity` `#BytoTech`)

## 9. Quality bar (pass / fail)

**Pass only if:**
- A stranger understands the offer by slide 3
- Brand name is visible every slide
- Dark/light rhythm is intentional
- Final slide makes the next action obvious
- Content matches Byto services and positioning

**Fail if:**
- Looks like a generic purple “AI agency” template
- Looks like an SMM growth agency
- Text is unreadable on mobile
- More than one competing message per slide
- CTA missing at the end
